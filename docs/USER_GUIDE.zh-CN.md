# dngscan 使用说明

这是一份不讲数学的说明书。它回答三个问题：这个工具能处理什么相机的照片、界面上的每个数字是什么意思、导出时该选什么。想了解管线原理和技术细节，请看 [README](../README.zh-CN.md)。[English version here](USER_GUIDE.md).

dngscan 做一件事：把 RAW 照片转成尽量忠实的 JPEG——普通 JPEG，或者在支持的屏幕上能真正亮起来的 HDR 照片（iPhone / Mac / 新款 Android 相册都能直接看）。

---

## 一、支持哪些相机

**默认解码器（LibRaw）**覆盖市面上绝大多数相机的 RAW 格式，包括但不限于：

| 品牌 | 格式 |
|---|---|
| 佳能 | CR2 / CR3 |
| 尼康 | NEF / NRW |
| 索尼 | ARW |
| 富士 | RAF（含 X-Trans 传感器） |
| 松下 / 奥之心 / 徕卡 / 宾得 | RW2 / ORF / DNG / PEF 等 |
| 适马、iPhone（ProRAW）及一切输出 DNG 的设备 | DNG |

装好就能用，不需要按机型安装插件。本工具的开发与校准主要在适马 fp 的 DNG 和 iPhone ProRAW 上完成，这些机型的体验经过最充分的验证；其余主流机型可以正常解码转换，遇到异常欢迎反馈样张。

**Apple RAW 解码器（可选，"解码器"选 Apple RAW）**使用 macOS 系统自带的 RAW 引擎，支持范围以 Apple 官方的相机 RAW 兼容列表为准——主流的佳能、尼康、索尼、富士、松下、适马机型和 iPhone 都在内，但**最新版解码模型（RAW 9）只对其中较新的机型开放**。不用自己查列表：选中文件后工具会自动探测这个文件支持到哪个版本，不支持时会明确提示并让你选择降级或改回 LibRaw，不会不吭声地换算法。

两个解码器出片的色彩性格略有不同（Apple 的降噪和高光重建更"相机厂商化"），都可以正常出 SDR 和 HDR。不确定就用默认的 LibRaw。

---

## 二、基本流程

1. **选文件**——顶部选择 RAW 文件；
2. **看"检测参数"**——工具已经分析了这张照片，先看这里再动手（下一节解释每个数字）；
3. **调曝光和明暗**——需要的话；
4. **选输出**——普通 JPEG 还是 HDR，发朋友圈还是存档（第五节）；
5. **更新预览确认，导出。**

---

## 三、"检测参数"里的数字是什么意思

这张卡显示的是工具对照片的测量结果，和最终渲染用的是同一套分析。

**先弄懂 EV**：EV 就是"档"，摄影里的曝光单位。+1 EV = 亮度翻倍，−1 EV = 亮度减半。本工具里所有 EV 都以**中灰**（曝光正确的 18% 灰，大致是正常曝光下人脸中间调的亮度）为 0 点：+3 EV 表示比中灰亮 3 档，−5 EV 表示比中灰暗 5 档。

| 字段 | 意思 | 有什么用 |
|---|---|---|
| **RAW 剪切** | 传感器上有多少比例的像素过曝溢出（"死白"） | 高说明高光烧了不少；这部分像素的颜色是猜出来的，工具会自动降低对它们的信任 |
| **可靠高光尾部** | 照片里最亮、且**真实测到没烧掉**的内容在几档（剪切像素已剔除，不算数） | 这是 HDR 亮度预算的唯一依据：夜景灯牌测到 +6 EV，HDR 就有底气把它点亮到 +6 |
| **HDR 可挣余量** | 可靠尾部里超出"纸白"（屏幕上正常白色）的部分 | 就是这张照片 HDR 能比普通照片额外亮多少档；为 0 说明这张图没有值得 HDR 的高光 |
| **主体中位** | 画面主体大致在几档 | 负得多说明整体偏暗（夜景），接近 0 说明曝光标准 |
| **场景类型** | 普通 / 稀疏光源 | "稀疏光源"= 夜景灯点、舞台这类大片黑+小片极亮的场景，工具会自动换一套更合适的高光策略 |
| **编译曲线** | 本次渲染实际采用的暗部到亮部范围和对比度 | 参考值，让你知道工具替这张图做了什么决定 |

**看这张卡的典型方式**：可挣余量 +1.5 EV → 值得导 HDR；RAW 剪切 8% → 天空可能烧了，高光模式试试"邻域重建"；主体中位 −3 EV → 这是夜景，别硬拉曝光。

## 四、界面上其他的 EV

- **曝光 EV**（曝光卡的滑块）：整体提亮/压暗，+1 = 亮一档。0 保留拍摄时的亮度关系。
- **亮度参考**（按钮）：让工具测量主体亮度并自动对齐到标准曝光，同时避免高光溢出。相当于"帮我曝光一次"，结果会写回曝光滑块，可以再手调。
- **HDR 余量上限**（输出卡）：你的屏幕/用途最多允许 HDR 比纸白亮几档，是**天花板不是目标**——实际用多少由"可挣余量"决定，两者取小。默认 +3.0（约对应 800 nit 屏幕）通常不用动。

## 五、压缩核心是什么，怎么选

RAW 记录的亮度范围远超屏幕能显示的范围，"压缩核心"就是把前者装进后者的方式——它决定照片的整体观感，尤其是高光的颜色表现。

| 选项 | 一句话 | 什么时候用 |
|---|---|---|
| **AgX · 默认** | 电影级的收高光方式：亮部自然褪向白色，颜色不会又艳又假 | **不确定就用它**，95% 的情况 |
| **RAW 门控 · 保真** | 和 AgX 同款亮度，但颜色处理的强度由 RAW 证据逐像素决定：传感器真实测到的颜色尽量保留 | 想要更"忠实于传感器"的颜色时；仅 LibRaw 解码可用 |
| **场景 C1 · 仅亮度** | 只压亮度、完全不动颜色比例 | 对照组：想看看"AgX 的颜色处理到底做了什么"时切来对比 |
| **固定亮度曲线 · 诊断** | 固定曲线，不看场景 | 排查问题用，日常不用 |

后两个是对照/诊断工具，不是给成片用的。

## 六、输出：格式与交付档

**格式**：
- **SDR JPEG**——普通照片，哪里都能看；
- **HDR gain-map · JPEG**——推荐的 HDR 格式。照片里同时装了普通版和高光增强信息，支持的屏幕（iPhone、Mac、Android 15+）上高光真的会亮起来，不支持的地方自动显示普通版，不会出错；
- **HDR gain-map · HEIC**——同样内容的 HEIC 容器。**实测它并不更小、画质还略差**，只有下游明确要求 HEIC 时才选。

**交付档**：
- **Archive · 保真**——最高质量（约 60MB/张），当高质量留底用；
- **Share · 流媒体**——发布用（约 11–27MB/张），肉眼基本无差、HDR 信息完整保留，**最大的照片也在微信"原图"25MB 限制之内**。

**发微信的注意事项**：聊天里必须勾"**原图**"，HDR 才能到达对方（iPhone 微信看原图有完整 HDR 效果）；**朋友圈一定会被压缩成普通照片**，这是微信的行为，任何工具都绕不过。重要交付走"文件"方式发送最保险。

**导出后看"投递报告"**：预览图上方那个可折叠面板，写着这次导出的实际情况——文件多大、HDR 实际用了几档、压缩造成的误差有多小。每张导出的文件都经过了自动校验，校验不过的文件不会被保留。

## 七、常见问题

**导 HDR 时报"可靠高光尾部不支持任何 HDR 余量"？**
这张照片没有测到真实的高光内容（检测参数里"HDR 可挣余量"为 0）。这不是故障——一张没有亮部的照片做成 HDR 也不会有任何区别，改导 SDR 即可。

**选 Apple RAW 后弹出提示说这个文件只支持 RAW 8？**
你的相机/文件不在 RAW 9 的支持范围。按提示选择用旧版本继续，或改回 LibRaw，两者都能正常出片。

**预览和导出会不一样吗？**
预览用低分辨率代理以求快，构图和色调一致；锐度、噪点观感以全尺寸导出为准。导出状态里标"全分辨率真值"的数字才是最终值。

**HDR 效果在哪里能看到？**
用 macOS 预览/访达、iPhone 相册、Android 15+ 相册或 Chrome 打开导出的文件。普通显示器/老系统上它就是一张正常的 JPEG。

**质量和色度采样为什么有时不能改？**
Archive 档按定义锁定最高质量；HDR 格式下色度采样由系统编码器按质量自动决定，工具如实显示而不是假装可调。
